Lakebase Insights moves to per-project settings, with on-demand runs (Beta)
> [翻訳エラー: Error code: 404 - {'type': 'error', 'error': {'type': 'not_found_error', 'message': 'model: claude-3-haiku-20240307'}, 'request_id': 'req_011CgFXZZE2SwzoaZZ4yVJJR'}]
October 19, 2026

Lakebase Insights now diagnoses issues using telemetry from the system.lakebase system tables and recommends next steps. The Lakebase Insights workspace preview enables automatic telemetry capture. Users with CAN MANAGE can configure Insights directly in each project's Settings, without creating an observability configuration.

This preview was previously named Lakebase Advanced Postgres Telemetry. Workspaces that used Insights before already have it enabled. To set up Insights:

  • If the preview isn't already enabled, ask a workspace admin to enable Lakebase Insights from the Previews page. Insights needs telemetry in system.lakebase to analyze a project, so enabling the Insights preview also enables Lakebase Observability in System Tables if it isn't already enabled. Workspace admins can enable the observability preview separately to capture telemetry without Insights.
  • To schedule Insights runs for a project, you need CAN MANAGE on that project. Enable Insights and set its analysis frequency in Settings.
  • You can run Insights on demand at any time, with or without a schedule.

If you scheduled Insights through an observability configuration, those jobs have stopped. Their schedules do not carry over. Those configurations no longer write telemetry to their Unity Catalog destinations, so their dashboards retain historical data but receive no new data.

To continue receiving scheduled insights, enable Insights and set an analysis frequency in each project's Settings. Each project runs separately, and each run uses compute and model tokens, so choose which projects to analyze and how often. Insights remains in Beta. See Detect issues with Insights.

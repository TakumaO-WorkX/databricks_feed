You can now copy an existing PostgreSQL database into a Lakebase project in a single, one-time migration. Lakebase assesses the source database for compatibility, then copies its roles, schema, and data to a branch that you choose. Migrations are available in the Lakebase App and through the Postgres API and SDKs, with no separate enablement step. See Migrate a Postgres database to Lakebase for migration steps and region availability.

Lakewatch streaming detection rules (Experimental)
> [翻訳エラー: Error code: 404 - {'type': 'error', 'error': {'type': 'not_found_error', 'message': 'model: claude-3-haiku-20240307'}, 'request_id': 'req_011ChPP676UDg4BABQT2XJFQ'}]
November 24, 2026

Lakewatch now supports streaming detection rules, which evaluate each new row of a source table as it arrives and create a signal for every row that matches a SQL predicate. Use them for low-latency signature, indicator of compromise (IOC), and atomic-signal detections. Lakewatch manages the compute, so you don't select a SQL warehouse or a schedule. Streaming rules are an experimental feature. See Streaming detection rules.

Genie Migrate conversion to Lakeflow pipelines is generally available
> [翻訳エラー: Error code: 404 - {'type': 'error', 'error': {'type': 'not_found_error', 'message': 'model: claude-3-haiku-20240307'}, 'request_id': 'req_011ChPP688E5Y6aSYPPMV8HR'}]
November 24, 2026

Genie Migrate conversion of T-SQL scripts from SQL Server and Azure Synapse dedicated SQL pools into Lakeflow pipelines is now generally available. In a T-SQL migration project, choose the Spark Declarative Pipelines target framework, organize your files into groups, and choose a catalog and schema for each group. Each group becomes one serverless pipeline that Genie Migrate validates with a dry run.

To use the Spark Declarative Pipelines target framework, a workspace admin must turn on Migration Projects Experimental Features from the Previews page. See Manage Databricks previews.

See Supported source dialects and target frameworks.
